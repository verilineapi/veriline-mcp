# MCP v1.1.0 branch plan (batch 2 tools)

Notes only — do not implement or publish until the batch 2 API.market listings are approved and their playground URLs are confirmed. Keep v1.0.0 on npm and the Official MCP Registry for the three live APIs until then.

## Branch

After v1.0.0 has been tagged and published from `main`:

```bash
git checkout main
git checkout -b feat/v1.1.0-batch2
```

Bump these three places together to `1.1.0`: `package.json`, `server.json` (`name` stays `io.github.verilineapi/veriline-mcp`), and `src/config.ts` (`PACKAGE_VERSION`). Update `CHANGELOG.md`. The Official Registry `description` must stay at or under 100 characters.

## New tools (5), same client and auth

Reuse `verilineGet`, `X-Gateway-Secret` / `x-api-market-key`, and the 5s default timeout. Add per-product bases derived from `VERILINE_API_BASE` plus slugs assigned at API.market submission (confirm against the playground; do not guess).

| Tool | HTTP | Product |
|---|---|---|
| `extract_page_markdown` | `GET /v1/extract?url=&include_links=&include_images=&main_content=&max_chars=` | Webpage to Clean Markdown & Metadata |
| `extract_page_metadata` | `GET /v1/metadata?url=` | same |
| `get_sec_company` | `GET /v1/company/{ticker_or_cik}` | SEC EDGAR Clean Company Financials |
| `get_sec_financials` | `GET /v1/financials/{ticker_or_cik}?period=&limit=` | same |
| `get_sec_filings` | `GET /v1/filings/{ticker_or_cik}?form=&limit=` | same |

Expected tool count after the bump: 11 (6 existing + 5 new). Do not add `/health` as a tool.

New env vars (optional overrides, same pattern as batch 1):

- `VERILINE_WEB_MARKDOWN_BASE` / `VERILINE_WEB_MARKDOWN_KEY`
- `VERILINE_SEC_FINANCIALS_BASE` / `VERILINE_SEC_FINANCIALS_KEY`

Declare the base overrides in `server.json` `environmentVariables` (not secret). Keep `VERILINE_API_KEY` as the required secret.

Default host remains `https://prod.api.market/api/v1/veriline`. Per-product URLs will be `{VERILINE_API_BASE}/<slug>` once slugs are known.
